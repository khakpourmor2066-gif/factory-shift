عنوان: Deploy and Recovery Runbook
تاریخ: 2026-07-28

وضعیت فعلی سرور:
- SSH با `root` و کلید `factory_shift_bale_mvp` فعال است.
- `nginx` فعال است.
- backend و postgres با `docker compose` بالا هستند.
- health endpoint پاسخ `{"status":"ok"}` می‌دهد.
- webhook Bale روی HTTPS فعال است.

آدرس‌ها:
- Health: `https://213.176.6.200.nip.io/health`
- Bale webhook: `https://213.176.6.200.nip.io/bot/bale/webhook/<BOT_WEBHOOK_SECRET>`
- Dashboard: `https://213.176.6.200.nip.io/admin/dashboard`

Deploy sequence:
1. از revision مورد تأیید GitHub یک archive بساز و آن را در `/opt/factory_shift` استخراج کن.
2. قبل از migration با `bash backend/tools/backup_prod_server.sh predeploy` از کد و PostgreSQL نسخه پشتیبان بگیر.
3. `docker compose --env-file .env.prod -f docker-compose.prod.yml run --rm --no-deps backend python -m alembic upgrade head`
4. `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build --no-deps backend`
5. `bash backend/tools/smoke_prod_server.sh https://213.176.6.200.nip.io`
6. `bash backend/tools/smoke_import_server.sh https://213.176.6.200.nip.io`
7. revision مستقرشده را فقط پس از موفقیت smoke در `.deployed_revision` ثبت کن.

Backup verification:
1. مسیر فایل `database_backup` را از خروجی ابزار backup بردار.
2. `bash backend/tools/verify_postgres_backup.sh <database_backup>` را اجرا کن.
3. فقط در صورت نمایش `restore_verified=true` پشتیبان را قابل بازیابی بدان.
4. ابزار verification از PostgreSQL موقت و ایزوله استفاده می‌کند و پس از پایان آن را حذف می‌کند.

Production smoke:
- health، readiness و dashboard را از مسیر عمومی بررسی می‌کند.
- `getMe` و `getWebhookInfo` بله را بدون چاپ token یا URL محرمانه بررسی می‌کند.
- برای شناسه جعلی پیام واقعی ارسال نمی‌کند.

Recovery sequence:
1. `docker compose -f docker-compose.prod.yml ps`
2. `docker logs factory_shift_backend --tail 200`
3. `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build backend`
4. `docker compose --env-file .env.prod -f docker-compose.prod.yml exec -T backend python -m tools.seed_access_demo`
5. `bash backend/tools/smoke_prod_server.sh https://213.176.6.200.nip.io`

Known caveat:
- اگر `docker compose` بدون `--env-file .env.prod` اجرا شود، warningهای `POSTGRES_PASSWORD` و `BOT_WEBHOOK_SECRET` ظاهر می‌شوند.
- برای استقرار پایدار، همیشه از `--env-file .env.prod` استفاده شود.
